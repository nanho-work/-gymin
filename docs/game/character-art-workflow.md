# 캐릭터 이미지·모션 제작 공통 절차

## 최우선 외형 기준 변경 (2026-10-26)

승급이 몸체·갑옷 외형을 결정한다. 얼굴·체격·크기는 유지하고 복식·보호 구조·재질로 강함과 세련됨을 표현한다. 장비 외형 교체는 무기·탈것(마갑 포함). 방어구 능력치·옵션은 유지하지만 갑옷 아이템마다 외형을 바꾸지 않는다. 이전 갑옷별 원칙보다 우선한다.
홍유 v2는 5시 정지 비교 시안. 기존 조작 리그는 경기병 기본 복장으로 유지하며 새 원화의 분리·4방향·모션 연결은 후속 제작.


## 현행 기준: 홍유에서 확정한 분리 제작 방식 (2026-10-26)

사용자가 현재 홍유의 방향·팔 배치 결과를 확인했다. 새 캐릭터에는 아래 제작 원칙을 적용한다. 이 절이 아래의 과거 홍유 좌표·반전 수정 이력보다 우선한다. 기존 160px 일체형 프레임 방식과 홍유의 320px 부품 조합 방식을 혼동하지 않는다. 현재 자세 확인은 완성된 보행·공격 애니메이션 전체의 승인과 다르다.

### 1. 먼저 그릴 것과 분리 경계

| 부품 | 제작 내용 | 교체·재사용 기준 |
| --- | --- | --- |
| 머리 | 앞/뒤 사선 얼굴·뒤통수, 목 접점 포함 | 몸체와 별도. 머리카락·장식의 비대칭은 별도 방향 원화 필요 |
| 몸통·옷·갑옷 | 무기·머리·팔을 제외한 옷 입은 몸체. 하마는 자락·바지·신발 포함 가능 | 장비마다 같은 목·어깨·허리 위치, 체격·카메라 각도 고정 |
| 오른팔·왼팔 | 어깨부터 소매·손까지. 무기 손과 빈손 자세 구분 | 어깨와 손 접점, 팔꿈치 굽힘 확인. 갑옷 소매·장갑도 변하면 팔 원화 추가 |
| 무기 | 손과 팔이 없는 단독 투명 이미지 | 손잡이의 잡는 지점 등록. 그 지점을 손에 붙이고 회전 |
| 기수 하체 | 말을 걸터앉은 자세의 양다리·신발 | 가까운 다리/먼 다리 별도 레이어 권장 |
| 탈것 | 기수 없는 말·안장 | 말마다 안장 높이·폭과 발굽 접지점 맞춤 |
| 마갑 | 탈것 위에 맞는 장비 | 현재 홍유는 마갑이 포함된 말 외형 교체. 별도 덧입히기 시스템 완성 아님 |
| 효과 | 발광·타격·스킬 효과 | 캐릭터/무기에 굽지 않고 별도 효과 레이어로 제작 |

모든 부품은 투명 배경, 동일한 시점·광원·윤곽선·상대 크기로 그린다. 연결부는 틈이 나지 않을 만큼 겹칠 여유를 둔다. 얼굴이나 팔이 갑옷 원화에 중복으로 들어가지 않게 한다. 최하급 무기 + 기본 옷/갑옷 + 보조 없음이 기본 모습이다.

### 2. 방향 번호와 실제 방향

| 번호 | 방향 | 보이는 면 |
| --- | --- | --- |
| ① | 11시 / NW | 뒤쪽 왼쪽 사선 |
| ② | 2시 / NE | 뒤쪽 오른쪽 사선 |
| ③ | 5시 / SE | 앞쪽 오른쪽 사선 |
| ④ | 7시 / SW | 앞쪽 왼쪽 사선 |

방향은 캐릭터가 바라보는 방향이다. 게임 맵의 상하좌우 이동 좌표는 별도로 연결한다. 같은 번호에서 머리·옷·팔·하체·말이 같은 방향을 보아야 한다. 파일명으로 추정하지 않고 합성 화면을 확인한다.

대칭 원화는 검증된 앞 사선(SE), 뒤 사선(NW)을 그려 SW/NE를 반전해 재사용할 수 있다. 다만 무기 손, 비대칭 복장·흉터·장식은 단순 전체 반전하면 안 된다. 결과는 반드시 4방향으로 검수하며, 반전으로 맞지 않는 방향은 따로 그린다.

### 3. 중심과 접점

- 합성 캔버스는 홍유 기준 320×320 논리 좌표. 부품 이미지의 해상도가 모두 320px이어야 한다는 뜻은 아니다.
- 기준은 몸통 중심선·허리 회전축·목·양쪽 어깨·양손·골반·지면. 기마는 안장 접점을 추가한다.
- R/L은 캐릭터 본인의 오른쪽/왼쪽이며 화면 좌우가 아니다. 홍유는 오른손이 무기 손이다.
- 장비를 바꿔도 몸 중심·얼굴·접지점이 흔들리면 안 된다. 부품마다 자동으로 여백을 제거하면 원점이 달라지므로 위치 정보를 함께 보관한다.
- 무기는 이미지 중앙이 아니라 손잡이 접점을 중심으로 회전한다. 팔은 어깨/손 연결과 팔꿈치 굽힘을 모두 확인한다.
- 홍유의 픽셀 좌표·반전 불리언·소매 굽힘 0.55 값은 해당 원화 전용 보정이다. 다른 캐릭터에 그대로 복사하지 않는다.

### 4. 탑승과 하마

기마 캐릭터는 두 자세가 필요하다. 머리·무기·일부 상체는 공유 가능하지만 기수 하체와 지상 하체는 다르다. 탑승용 팔 자세도 필요에 따라 따로 그린다.

현재 홍유는 하마 몸체(옷·갑옷·하의 한 벌)의 상단 65%를 탑승 상체로 재사용하고 기수 다리를 조합한다. 탑승 전신과 하마 전신을 장비마다 모두 별도 제작한 구조가 아니다. 옷자락이나 안장에 맞지 않으면 전용 탑승 몸체를 제작한다.

보병·책사 등 타지 않는 캐릭터는 지상 자세만 제작한다. 하마 대기를 만들었다고 걷기가 완성되는 것은 아니다. 지상 이동에는 무게 이동과 다리 보행 자세가 추가로 필요하다.

### 5. 앞뒤 가림 순서

- 탑승 기본: 먼 다리 → 말 → 가까운 다리 → 상체. 현재는 한 다리 원화의 반쪽씩을 클립하지만 신규 제작은 양다리를 분리하는 편이 안정적이다.
- 후면에서 몸 앞에 든 창·팔은 등보다 먼저 그려 등이 가리게 한다. 팔을 무조건 마지막에 그리면 등 위로 팔이 튀어나온다.
- 앞면은 먼 팔과 가까운 팔을 구분하고 창과 잡는 손의 관계를 맞춘다.
- 위 순서는 홍유 현재 자세 기준이다. 팔을 벌리거나 머리 위로 드는 새 동작은 프레임별로 가림 순서를 정한다. 모든 동작에 고정된 순서를 강제하지 않는다.

### 6. 무기 회전과 별도 원화가 필요한 경우

홍유는 무기당 SE 단독 원화를 재사용하며 좌우반전·손 중심 회전으로 움직인다. 이는 화면 평면에서의 회전이다. 원근 단축, 창끝이 화면을 향하는 찌르기, 무기 앞/뒷면 전환, 휘어지는 활, 손잡이 교체는 단순 회전으로 표현할 수 없어 방향/동작 원화가 추가로 필요하다.

옷과 탈것도 방향 이미지만으로 정지 외형은 교체할 수 있으나, 걷는 발·펄럭이는 옷·움직이는 말다리는 별도 동작 프레임 또는 관절 부품이 필요하다. 현재 홍유 이동은 부품 흔들림 초안이며 완성된 말 보행이 아니다. 하마는 대기만 지원한다.

### 7. 새 캐릭터 작업 순서와 완료 기준

1. 체격·기본 복장·주무기 손·보병/기마 여부 결정.
2. 최하급 장비로 4방향 정지 자세를 제작. 기마는 탑승/하마 8개 자세를 먼저 확인.
3. 부품별 접점·실제 원화 방향·반전 여부·가림 순서 기록.
4. 동일 장면에서 번호별로 확대 비교. 머리 방향, 양팔 굽힘, 손잡이 접점, 다리 가림 확인. 사용자가 자세를 확인하기 전 장비를 대량 확장하지 않는다.
5. 무기 한 종·갑옷 한 종 교체해 체격/중심/접점이 유지되는지 확인. 기마는 탈것 한 종도 비교.
6. 확인된 기본 자세에 대기→이동→공격→스킬 순서로 동작 추가. 극단 자세와 프레임 전환까지 검수.
7. 나머지 장비 확장. 얼굴·원본 병과·이동거리·능력치는 외형 작업으로 변경하지 않는다.
8. 모바일 표시 크기에서도 빈틈·겹침·무기 잘림·인접 프레임 혼입·발 위치 흔들림을 확인.

수치검사는 누락·접점·변환·가림 순서 회귀를 잡는 보조 수단이다. 시각적으로 정상이라는 근거를 대신하지 않는다. 홍유 검사 명령은 `node scripts/game/check-hong-rig.cjs`이며 다른 원화는 그 원화에 맞는 검사가 필요하다.

### 8. 용량과 기록

작은 투명 WebP 부품을 공유하고 장비 조합마다 완성 전신 파일을 복제하지 않는다. 생성 원본은 경량본 검수·연결 후 작업 규칙대로 정리한다. 원화 프롬프트, 실제 방향, 목/어깨/손/안장/접지점, 반전·가림 규칙, 사용 파일, 파일 크기를 기록한다. 커밋·푸시·배포는 사용자 담당이다.


## 이전 공통 규격과 제작 이력

아래 홍유 좌표·반전 관련 항목은 수정 과정의 기록이다. 현행 제작 기준은 문서 상단을 따른다.

## 파일과 화면 규격

- 기존 전신 콘셉트를 정체성 기준으로 삼는다. 얼굴·재질·의상·소품을 유지한다.
- 프로필은 전신 축소가 아니라 얼굴과 어깨를 새로 구성한 전용 초상화다. 머리 전체가 들어가고 얼굴이 화면의 약 60%를 차지하게 한다. 128×160 WebP, 품질 76 전후.
- 전신 콘셉트는 최대 512px WebP. 카드 배치는 왼쪽 초상화 → 가운데 이름(교체 이름이 있으면 함께) → 오른쪽 전신이다.
- 모션은 11·2·5·7시 방향별로 대기·이동·공격·스킬 각 4프레임을 기본 초안으로 한다. 방향 그림과 게임 좌표의 이동 방향을 구분한다.
- 프레임은 160×160 투명 WebP, 품질 72 전후. 개별 프레임을 사용하여 인접 프레임 혼입을 막는다. 한 캐릭터 64장 합계 약 400KB를 목표로 실제 용량을 기록한다.

## 제작·검수 순서

1. 원본 콘셉트를 열어 확인하고 내장 이미지 생성 도구의 참조 이미지로 사용한다. 초상화는 얼굴 중심으로, 모션은 방향별 시트로 생성한다.
2. 모션 시트에는 일정한 캐릭터 크기, 발 접지 높이, 충분한 투명 여백, 이웃 캐릭터와 분리된 소품을 요구한다.
3. 생성 시트를 먼저 시각적으로 확인한다. 방향 오류·무기 변형·붙은 실루엣은 재생 코드로 숨기지 말고 재제작한다.
4. `node scripts/game/pack-character-motion.mjs <설정 JSON>`으로 분리한다. 설정은 `asset`(소문자 영문·숫자·하이픈)과 `entries`(방향 id 및 source 파일 경로)를 포함한다.
5. 도구는 행별 연결 영역을 추출해 캐릭터를 분리하고, 접지 영역의 중심과 하단 기준선을 정렬한다. 무기·장식이 발보다 아래로 내려가면 자동 정렬만으로 발 위치를 보장할 수 없으므로 반드시 확인한다.
6. 자동 추출 결과는 완성 판정이 아니다. 얼굴·손·발·소품이 빠지거나 이웃 그림이 붙었는지 모든 프레임의 비교 이미지로 확인한다. 크기·발 기준점·방향 일관성도 점검한다.
7. `folklore-plan.json`의 `portrait`, `image`, `motion`에 연결한다. 공통 `CharacterMotion`은 이름과 자산 폴더를 받아 방향·동작·재생·정지·프레임 이동을 제공한다.
8. 빌드와 브라우저에서 이미지 로딩 및 방향·동작 전환을 확인한다. 검증한 것과 남은 시각적 보완을 구분한다.
9. 경량 파일과 생성 프롬프트·자산 목록을 보존한다. 확인이 끝나면 해당 작업의 대형 생성 원본과 불필요한 복사본만 삭제한다. 다른 작업 파일은 삭제하지 않는다.
10. 커밋·푸시·배포는 사용자가 한다.

## 초안과 완성의 구분

생성 프레임은 프레임 간 형태 변화가 있을 수 있다. 연결·정렬이 끝났다는 이유로 게임용 최종 모션 또는 고증 완료라고 표시하지 않는다. 이동 미리보기는 기본적으로 제자리 걷기이며, 실제 맵 이동은 별도 게임 로직이다.

## 현재 적용과 검증 범위 (2026-10-25)

- 설화 후보 10명: 초상화 128×160, 모션 160×160 총 640프레임. 용량은 `scripts/game/folklore-art-v2-manifest.json` 참고.
- 큰 사족보행 캐릭터는 설정의 `bodyHeight`로 전체 방향의 기준 크기를 조절한다(쇠동 88, 기본 104). 프레임마다 다른 비율로 축소하지 않는다.
- 전체 파일 크기·알파·누락 확인, Next 빌드 성공, 브라우저 10개 카드 로딩 및 방향·공격·스킬·프레임 전환 확인.
- 생성 시트의 일부 시선 각도와 형상 일관성, 공격 복귀 및 걷기 연결은 추가 보완 대상이다. 자동 기준선은 소품/꼬리 하단을 발로 판단할 수 있으므로 최종 게임용 피벗 검수를 별도로 한다.

- 모바일 플레이 외형은 초상화와 별개로 작은 표시 크기에서 검토한다. 홍유 중기병5시 정지 시안과 프롬프트는 [hong-mobile-readability-v1.md](hong-mobile-readability-v1.md) 참고. 아직 전 방향 공통 기준으로 확정한 것은 아니다.


홍유 모바일 기본 외형(3승급·4방향·탑승/하마) 제작 기준: [문서](hong-mobile-rig-v1.md). 무기·말은 기존 교체 구조를 유지하며 새 인물에도 팔 접점과 방향 규칙을 공통 적용한다.


나머지 이름 있는 기마 계열 55명 초상화와 동일 인물 5개 공유: [전체 제작표·프롬프트](remaining-mounted-portraits-v1.md). 캐릭터의 가칭과 병과를 유지하고 얼굴·나이·군장으로 구분한다.


## 문서 선행 제작 기준 · 2026-10-26

신규 초상화는 [미제작 인물 전체 설계안](unmade-character-portrait-plan.md)을 먼저 검토한다. 인물별 성별·표현 나이·얼굴·체격·복식·머리/관모·수염·흉터를 정하고 그림체만 공유한다. 문서 제안을 설정 확정으로 간주하지 않는다. 사용자 검토 전 대량 생성을 시작하지 않는다.


문서 기반 86명 초상화 제작 완료: [프롬프트·결과](planned-portraits86-v1.md). 인물 설정은 제안, 초상화는 적용 상태로 구분한다.
