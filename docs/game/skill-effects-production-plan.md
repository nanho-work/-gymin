# 스킬 이펙트 제작 계획 및 작업자 지침

2026-10-30 · 검토용 제작안. 이번 단계는 글 기획이며 이미지 일괄 생성 승인을 의미하지 않는다.

## 목적과 기준 자료

현재 68개 스킬을 시각적으로 비교하는 기획 사이트의 에셋 제작 계획이다. 게임 실행 엔진의 완성이나 실제 전투 적용을 뜻하지 않는다. 기능·MP·사거리·범위·습득 병과는 그대로 둔다.

- 기능: `web/src/features/game-world/data/skills.json`
- 후보 명칭과 효과 설명: `web/src/features/game-world/data/skill-candidates.json`
- 범위 도식: `web/src/features/game-world/components/SkillRange.tsx`
- 기존 화염: `docs/game/fire-effects-v1.md`, `docs/game/fireball-effect-v1.md`

명칭은 후보이며 id가 연결 기준이다. 원본 area/range 숫자는 칸 수가 아니다. 각 스킬의 범위 도식과 설명을 함께 확인한다. 자료 사이에 모순이 있으면 임의로 기능을 정하지 말고 이슈로 보고한다.

## 공통 화면 연출

시전자 기존 스킬 모션 → 필요한 경우 투사체 이동 → 대상 효과 → 잔상 소멸 순서다. 캐릭터를 이펙트에 그려 넣지 않는다. 단일/광역은 대상을 중심으로 재생하며, 광역 범위와 실제 판정은 별도 메타데이터다. 그림이 큰 것과 공격 범위가 큰 것은 다르다.

피해·상태이상을 따로 판정하는 기술은 타격과 성공 표시를 분리한다. 즉사 실패 시 적이 사라지는 연출을 하지 않는다. 버프의 반대 효과 상쇄도 실제 결과가 정해진 뒤 표시한다. 지금 사이트에서는 성공/실패 예시임을 명시한다.

상태 아이콘은 전투가 제공하는 별도 표시이며 긴 지속 이펙트를 이번 1회 시전 시트에 포함하지 않는다. 무작위 기술은 신령 등장 공통 연출과 결과별 연출을 분리한다.

## 그림체와 파일 규격

- 기존 화염의 제한된 색, 명확한 밝은 핵과 어두운 외곽, 작은 화면에서 읽히는 덩어리를 기준으로 한다. 사진 질감·미세 장식·과도한 무지개 빛 금지.
- 물: 청록/푸른색과 흰 포말. 바람: 옅은 청록/백색의 호와 소용돌이. 대지: 황토/암갈/모래색. 회복: 연녹/크림. MP: 청색/보라. 약화: 어두운 보라. 색뿐 아니라 실루엣도 달라야 한다.
- 기본 8프레임, 4열2행, 셀128×128, 시트512×256 투명 WebP. 투사체가 필요하면 4프레임 시트를 별도로 추가한다. 표에 지정한 복합 연출·용·특수 소환은 필요할 때 12프레임(4열3행)을 허용한다. 아래 표 프레임 수는 제안이며 임의 확장 금지.
- 공통 축소 비율·고정 기준점, 최대 윤곽은 셀 중앙104px 안. 프레임마다 자동 맞춤 확대 금지. 셀 경계 침범, 옆 프레임 노출, 잔상 배경 금지.
- 지면 효과 anchor는 (64,100), 공중 효과 anchor는 (64,64). 메타데이터로 구분하고 프레임마다 동일 유지.
- 기본 100~120ms/frame. 시작-성장-정점-소멸이 이어져야 한다. 단순 좌우 흔들기나 같은 그림 복제는 신규 애니메이션으로 세지 않는다.
- 일반 시트 목표 60KB 이하, 특수 소환100KB 이하. 넘으면 크기/품질 조절 후 육안 확인하고 사유 보고. 투명 테두리 손상 금지.
- 모바일 실제 표시 96px 및128px, 밝고 어두운 배경에서 검수. 전체 화면 섬광·빠른 점멸·과한 화면 흔들림 금지.
- 방향성 없는 대상 효과는 4방향 불필요. 투사체·직선 효과만 방향 정책을 기록한다. 평면 불꽃/선은 회전 가능하지만 용·새·낙하 그림은 단순 회전하지 않는다.

## 재사용 원칙

단일/광역 힐과 버프는 동일 에셋을 실제 대상 칸에 재생하고, 강도는 별도 단계나 밝기/밀도로 구별한다. 공용화해도 68개 id별 연결과 설명은 빠짐없이 작성한다. 68개 스킬이 68개 독립 시트일 필요는 없다.

이미 있는 화염6종은 보존한다. 새로운 규격을 맞춘다는 이유로 전부 재생성하지 않는다. 불꽃 용과 물/바람/대지 용은 같은 실루엣 복사에 색만 바꾸지 않고 해당 속성의 움직임으로 구별한다.

## 분담과 진행 순서

이번 글 기획은 세 작업자에게 5–24 / 25–49 / 50–67을 나눴으며, 조정 담당이 기존0–4와65를 함께 점검한다. 이미지 제작 시 담당은 아래와 같이 고정한다.

| 작업자 | 담당 id | 담당 범위 |
|---|---|---|
| A | 5–24 | 물·바람·대지·흡수·둔화 |
| B | 25–49 | 약화·상태이상·회복·정화·이동/민첩 |
| C | 50–64,66–67 | 강화·날씨·특수·청룡/현무/백호 |
| 통합 담당 | 0–4,65 및 전체 연결 | 기존 화염 보존·명세 검토·공용화・페이지 연결 |

1. 글 계획 검토 후 각 담당 대표 1종(물살, 힐, 방어 강화)을 제작한다.
2. 통합 담당이 화염과 그림체·크기·재생을 비교한 뒤 나머지 묶음을 진행한다.
3. 각 담당은 3~5종 단위로 납품하고 검수 통과한 파일만 다음 단계로 넘긴다.
4. 공통 컴포넌트·데이터 연결은 통합 담당만 수정한다. 개별 담당은 자기 폴더만 작성한다.
5. 커밋·푸시·배포는 사용자 담당이다.

## 작업자에게 그대로 전달할 지침

당신은 스킬 VFX 제작 담당이다. 이 문서와 담당 id별 표, 원본 데이터, 기존 화염 경량본을 먼저 확인한다. 배정되지 않은 id와 소스 코드를 변경하지 않는다. 먼저 대표1종만 제작하여 검토를 요청한다. 기능을 바꾸거나 결과 미확정 상태에서 성공 연출을 강제하지 않는다. 이미지 생성은 imagegen skill을 읽고 내장 생성 도구로 진행한다.

납품 폴더는 `web/public/images/skills/batch-{a|b|c}/skill-{id}/v1/`이며, 생성 프롬프트와 manifest는 `docs/game/skill-effects/batch-{a|b|c}/`에 저장한다. 여러 id가 같은 에셋을 쓰면 manifest에 alias를 명시하고 파일을 복제하지 않는다. 경량본과 페이지 확인이 끝난 뒤 자신이 생성한 큰 원본만 정리하며 다른 작업자의 파일은 삭제하지 않는다.

manifest 필수: id, 후보명, 상태(draft/reviewed), 파일 경로, 실제 바이트·치수, cols/rows/frameCount, frameMs, anchor, 재생 구간, 투사체/명중/성공결과 역할, 대상 배치 정책, 방향 정책, 공유 id, 생성 프롬프트, 검수 결과와 미해결 문제. reviewed는 사용자 최종 승인이라는 뜻이 아니다.

## 검수 및 통합 완료 기준

- id0~67 정확히68개가 계획에 있으며, 파일 준비 여부·검수 여부·사이트 연결 여부를 따로 관리한다.
- 경량 파일 존재, 투명 배경, 시트 규격, 빈 프레임 여부, 모든 셀 끝부분 잘림을 점검한다.
- 처음/끝과 반복 재생을 확인하고 프레임 이동으로 중심 흔들림·인접 셀 침범을 확인한다.
- 원본 기능과 범위에 없는 연쇄 피해·빙결·완전 회복·부활을 그림이나 설명으로 암시하지 않는다.
- 실제 페이지 재생, 모바일 축소, 검색/필터의 id 연결을 확인한다. 통합 후 빌드는 한 번 실행한다.
- 완료 보고에는 생성 수가 아닌 연결된 스킬 id, 공유 에셋 수, 용량, 검사 범위, 미완성 항목을 쓴다.

### 작업자 전달 주의

- ID 50–56은 이름의 광역 여부보다 원본 범위를 먼저 따른다. 특히 **격려 ID 51은 십자 5칸**이다.
- 강화의 반대 효과 상쇄는 기존 규칙이다. 렌더러가 임의로 강화 성공을 판정하거나 항상 강화 아이콘을 남기지 않는다.
- 소환은 큰 전장 PNG를 만들지 않고 작은 소환체와 타격/회복 공통 부품으로 나눈다. 캐릭터 몸체와 분리된 VFX 자산이라는 의미이며, 캐릭터를 관절 분할하는 방식이 아니다.
- 청룡/현무의 무작위 결과와 기상 조건은 제작자가 창작하지 않는다. UI는 제작 검토용 예시, 실제 게임 판정은 별도이다.
- ID 65는 이미 제작된 파일을 재사용하므로 새 생성 수량에서 제외한다.
