# 지도 위 스킬·도구 조작

2026-10-31. Unity 실행·실제 화면 검수·커밋·푸시는 사용자 담당이다. 이 작업에서는 에디터/Play를 실행하지 않았다.

## 조작

1. 행동 가능한 부대를 선택한다. 이동 후에도 선택 가능하다.
2. 지도 오른쪽 아래 **스킬** 또는 **도구**를 누른다. 스킬은 현재 병과/레벨과 장비의 인접 습득 복사 규칙에 따른 목록, 도구는 실제 보유한 사용 가능 소모품만 표시한다. 이름/설명은 사이트의 현재 교체 후보 데이터를 공유한다.
3. 이름·MP 또는 보유 수량·설명을 보고 선택한다. 사용할 수 없으면 MP/날씨/상태/보옥 조건 이유가 표시되며 선택 버튼을 비활성화한다. 목록이 길면 이전/다음으로 넘긴다. 사거리 안에 대상이 없어도 스킬을 골라 범위를 미리 볼 수 있지만 사용 확정은 할 수 없다.
4. 지도에 **파랑 사거리**, **초록 선택 가능한 부대**를 표시한다. 부대를 누르면 **주황 효과 범위**, **노랑 영향 후보**, 대상 이름/후보 수가 나온다. 범위 안 부대라고 반드시 명중하는 것은 아니며 명중과 효과 판정은 원본 엔진이 담당한다.
5. **사용**으로 확정한다. **취소**는 MP·수량·행동을 소비하지 않는다. 이동 취소는 별도 기능이다. 전체/자기 중심 스킬은 시전자 자신을 선택한다.

도구는 자신 또는 주변8칸의 살아 있는 아군/동맹을 대상으로 한다. 회복·상태 해제·열매·성장·승급 조건은 기존 엔진을 사용한다. 승급 패는 원본 레벨/병과 조건을 만족해야 한다. 첫 전투 초기에 보유 소모품이 없으면 빈 목록이 정상이다. 테스트용 소모품을 게임에 추가하지 않았다.

## 판정과 완료 경계

- BattleActionQuery.swift: 기존 OriginalSpells.available/rejection/rangeContains/targets, AreaRules.cells, CampaignState.itemEffectAllowed를 읽기 전용으로 호출한다. 수동 controlMode=7과 AI 대상 제한을 섞지 않는다. 수동 회복의 만피 대상 등을 임의로 제외하지 않는다. 미리보기는 난수/전투 수치/소지품을 변경하지 않는다.
- actions는 스킬/도구 목록, aim은 사거리/효과 범위/유효 대상/영향 후보를 응답한다. 시전/사용 직전에도 같은 판정을 재확인한다. 잘못된 대상 선택은 취소 가능한 오류로 반환하며 전투 전체 실패로 처리하지 않는다.
- 스킬은 원본 staged cast와 기존 연출 완료 토큰을 사용한다. 도구는 머리 위 아이콘과 사용 모션/효과음41 이후 실제 효과·1개 차감을 확정한다. 잘못된/중복 완료 토큰은 기존 계약대로 거부한다.
- stateVersion=3, hasAim을 명시한다. JsonUtility가 누락 객체를 기본값으로 만드는 문제를 피한다. 이전 네이티브 파일은 재빌드 필요 오류를 낸다.
- BattleActionSelection은 순수 C# 대상 선택/확정 상태다. 다른 스킬의 오래된 미리보기나 취소 후 응답으로 사용 버튼이 활성화되지 않는다.
- BattleHud는 목록/확정, BattleBoardView와 재사용 셀 풀은 범위 표시, BattleController는 명령과 연출 완료 응답, ItemUseView는 사용 아이콘을 담당한다. UI가 전투 수식이나 판정을 재구현하지 않는다.

## 에셋과 생성

- node scripts/game/export-unity-actions.mjs: 현재 스킬68개 이름/설명과 소모품17개 이름/설명/48×48 아이콘. 아이콘 합계32,453바이트.
- node scripts/game/export-unity-effects.mjs: 스킬68개 레코드, 원본 공유 아틀라스34개, 합계283,343바이트. 기존8개 스킬 한정을 해제했다. 공유 이펙트를 중복 저장하지 않는다.
- 원본 매핑이 -1인 스킬38·58·59·60·66은 별도 이미지 연출이 없다. 해당 스킬은 시전자 동작과 실제 효과 단계로 진행하며 없는 원본 이펙트를 만들었다고 표시하지 않는다.
- 각 추출 아틀라스는4096 이내이며 기존 GeneratedTextureImport의 Point/무압축/NPOT 유지 설정을 사용한다. 도구 아이콘은 공용 TextureCatalog에서 읽는다.
- 위 두 exporter 이후 node scripts/game/build-unity-native.mjs를 실행한다. action-labels.json을 네이티브 폴더에도 복사한다. 새 환경의 전체 생성 순서는 [첫 전투 실행 연결](first-stage-runtime.md)을 따른다.

## 검사 결과와 한계

- node scripts/game/build-unity-native.mjs --check-actions: 격리된 메모리 fixture. 수동 만피 회복, 적/아군 구분, MP 부족, 실제 소지품 수량, 사거리, 원본 범위 셀, 승급 조건, 미리보기 무변경, 실제 도구 효과/1개 차감, staged 시전의 MP1회 차감/행동 완료 통과. 원본 데이터·사용자 저장은 수정하지 않는다.
- python3 scripts/game/unity/tests/native-actions.py unity/Assets/StreamingAssets/SanhaNative: 원본 B00의2턴 등장 뒤 목록·이동·대상/범위 조회·실제 시전·잘못된 완료 토큰 거부·MP 차감까지287개 JSON 명령 통과. 테스트 완료 응답을 주는 검사이며 화면/음향 재생 검증은 아니다.
- node scripts/game/unity/check.mjs --compile-unity: Node5개, 기존 순수 C# 검사, 신규 대상 선택/확정/취소/오래된 응답 거부, 한글 UTF-8 프로세스 왕복, 설치된 Unity DLL 대상 Runtime/Editor 컴파일 통과.
- Unity import/Play, 모바일 터치 HUD 배치와 이펙트 외형은 이번 작업에서 확인하지 않았다. 현재 실제 전투 백엔드는 macOS 전용이며, 모바일 입력 지원을 모바일 앱 빌드 완료로 취급하지 않는다.
