# 전투 결과 표시

2026-10-31. Unity 실행·수동 시각 검수·커밋·푸시는 사용자 담당이다.

## 표시

- 대상 위에 빨강 HP 피해, 초록 HP 회복, 파랑 MP 증감을 띄운다. 색과 함께 HP/MP·증감 부호를 표기한다.
- 실제 물리 공격 판정의 치명타는 금색 **치명타!**, 명중 실패는 **빗나감**, 명중했으나 실제 피해가0이면 **피해 없음**으로 구분한다. 치명타 난수는 빗나감과 함께 기록될 수도 있으므로 빗나감 표시를 우선한다.
- 실제 상한 적용 후의 변화량을 표시한다. 남은 HP보다 큰 피해나 최대 HP를 넘는 회복을 숫자로 부풀리지 않는다. MP 흡수/방어와 시전자의 MP 소모도 별도 결과다.
- 대상 머리 위의 작은 HP·MP 바/현재값과 선택 부대 HUD 수치를0.5초 동안 이어서 표시한다. 숫자는 위로 떠오르며 약1.1초 후 사라지고, 바는 약2.1초 유지한다.
- 다중 대상/반격/연속 공격은 각 부대 위치에 표시한다. 겹치는 숫자는 위쪽으로 분산하며 화면 안전 영역을 고려한다. 새 이미지나 폰트 파일은 추가하지 않는다.
- 회복·강화와 빗나감에 피해 점멸을 넣지 않는다. 실제 HP 감소가 있는 결과에만 기존 피격 점멸을 호출한다.

## 데이터와 완료 경계

- 원본 Swift 소스와 전투 수식은 수정하지 않는다. BattleFeedback.swift는 이전/이후 실제 CampaignUnit의 HP·MP와 기존 실행 단계의 명중·치명타 사실을 읽는다. 난수는 다시 뽑지 않는다.
- 각 명령의 상태 변경 후 combatResult 대기를 만들고 결과 목록을 제공한다. 클라이언트는 도착 시점에 한 번 표시해 수치가 최종값으로 먼저 튀었다가 되돌아오는 것을 방지한다. 기존 고유 완료 토큰을 사용하며, 표시 대기 완료 후에만 다음 엔진 단계로 진행한다.
- 결과는 HP/MP 변경을 재실행하는 명령이 아니다. 잘못된/중복 완료 응답으로 피해나 소모가 다시 적용되지 않는다. 결과 토큰으로 클라이언트 중복 표시도 막는다.
- 물리 결과는 PhysicalStrikeStage의 실제 대상/명중/치명타와 해당 패널 완료 후 상태를 사용한다. 범위 공격·반격·연속 공격의 대상 인덱스를 고정 주연 슬롯으로 추정하지 않는다.
- 피해 스킬의 명중 실패는 원본에 저장된 피해 이벤트 기준으로 표시한다. 회복 스킬의0회복은 회복 없음이다. 상태 전용 스킬은 엔진이 개별 명중 난수 결과를 저장하지 않으므로 상태가 같다는 이유만으로 빗나감이라고 추정하지 않는다. 스킬에 없는 치명타를 추가하지 않는다.
- 처음 등장하는 숨김 부대의 초기 HP는 회복량으로 표시하지 않는다. 새 게임/화면 이탈 시 기존 팝업을 정리한다.
- 네이티브 stateVersion=3과 C# DTO를 함께 갱신한다. 이전 실행파일은 갱신 안내를 낸다. build-unity-native.mjs로 현재 로컬 실행파일도 재생성했다.

Core는 CombatFeedback의 데이터/문구/표시 보간, Presentation은 CombatFeedbackView와 지도 투영, Controller는 결과 수신/완료 응답, Native 어댑터는 실제 상태 변화와 판정 사실의 전달을 담당한다. 화면의 보간값은 전투 판정을 변경하지 않는다.

## 관련 검사

- node scripts/game/build-unity-native.mjs --check-feedback: 실제 물리 실행 단계32개 fixture에서 치명타·빗나감·반격 대상/수치 일치, 실제 staged 힐과 MP 소모, 상한·치명 피해·MP 손실·등장 제외·난수 무변경 검사 통과.
- python3 scripts/game/unity/tests/native-actions.py unity/Assets/StreamingAssets/SanhaNative: 원본 B00 통신287개 명령에서 결과의 HP·MP가 엔진 상태와 같고, 스킬 소모·완료 토큰 보호가 유지되는 것 확인. 자동 완료 응답 검사이며 화면/음향 재생 검증이 아니다.
- node scripts/game/unity/check.mjs --compile-unity: 결과 문구·빗나감/0피해/치명타 구분·회복·HP/MP 보간과 기존 관련 검사, 설치된 Unity DLL 대상 Runtime/Editor 컴파일 통과.
- 실제 Unity 렌더링·터치·화면별 외형은 이번 작업에서 실행하지 않았다.
