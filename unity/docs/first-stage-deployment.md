# B00 초기 병력 배치 연결

2026-10-30. 원본 배치 좌표·진영·레벨을 유지하고 제작된 완성 캐릭터의 대기 첫 프레임을 연결했다.

## 표시 시점과 근거

- 기준은 S_00 setup 완료 후, 턴 이벤트·AI 실행 전이다. first-battle.json의 배치와 battle-00.json의70/71/75행을 대조한다. 도입 명령83의235/334 퇴장도 반영한다. 기존 Swift CampaignState.init(data:)의 초기 처리와 동일한 병력 구분이다. 새 바이너리 분석을 수행한 것은 아니다.
- 전장 동맹3명·적군14명, 등장 대기7명, 도입 퇴장2명. 총26레코드. 숨김/퇴장 병력은 전장 점유·렌더링에서 제외한다. 준비 명단에서는 구분해서 표시한다.
- 원본에서 왕건(조조)은 숨김으로 시작하며2턴 이벤트에 등장 명령이 있다. 이를 처음부터 배치하는 식으로 바꾸지 않았다. 턴 이벤트 자동 실행은 아직 연결 전이다.
- 출처의 setup 설명 블록만 순회하고 알려진 배치·퇴장·방향 정보를 읽는다. 조건 분기가 추가되면 변환을 실패시킨다. 전체 EEX 인터프리터 구현으로 취급하지 않는다.
- 방향0/1/2/3은 제작 에셋 nw/ne/se/sw로 연결했다. 원본 초기 방향과 setup의79 방향 명령을 사용했다.
- 왕건·견훤은 기존 전용 군주 에셋, 나머지는 원본 병과와 같은 제작 병과 에셋을 공유한다. 지휘관별 신규 전용 작화를 추가하지 않았다.
- 에셋은 투명 여백을 잘라 최대128px PNG로 변환하고 발 위치를 칸 하단에 맞췄다. 원본 WebP는 보존. 12개 공유 이미지 총82,381바이트.
- 원본 배경·지형은 변경 없음. 장비별 외형 변경 없음. HP/MP·전투 수치 계산, 이동·공격·턴 이벤트는 후속 단계이며 임의 수치를 표시하지 않는다.

## 재생성·검증

- 순서: export-unity.mjs → export-unity-board.mjs → export-unity-units.mjs. 원본 경로는 기존 SANHA_ORIGINAL_ASSETS. 생성물 직접 편집 금지.
- 원본/매핑/이미지 해시와 제한: unity/units-export-manifest.json.
- Node5개 검사 통과: 좌표/진영/레벨 보존,17/7/2 구분, 원본 변경/에셋 누락/미지원 조건 거절. C# 점유 검사에서는 대기 병력이 칸을 차지하지 않는지, 실제 병력 충돌이 거절되는지 확인.
- 외부 Unity DLL 컴파일 통과. 실제 Unity Validate Campaign에서 전체 대본·전장·유닛 텍스처 로드 성공.
- Play에서 출진 명단, 전장17개 렌더링과 초록/빨강 진영 표시 확인. (9,11) 도무겸/장보·도사·Lv5, (10,17) 동맹 보병1 선택 및 확대 표시 확인.
- 선택은 칸 기준이다. 머리가 윗칸에 걸쳐도 병력 발밑 칸이 점유 위치다.
- 다음: 이동/행동의 공통 상태, 원본 턴·등장 이벤트, HP/MP 계산과 표시 순으로 연결.

## 런타임 갱신

정지 배치는 입력 스냅샷으로 보존한다. 실제 Game 씬의 위치·HP/MP·등장/퇴장은 기존 엔진 상태를 사용한다. 왕건의2턴 등장과 조작/AI 연결은 [첫 전투 실행 연결](first-stage-runtime.md) 참조.
