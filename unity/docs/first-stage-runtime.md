# 첫 전투 macOS 실행 연결

2026-10-30. 웹은 기획 검토용이며, Game 씬은 실제 전투를 실행한다. 이번 단계는 B00 하나를 끝까지 시험할 수 있는 macOS 개발판이다. 커밋·푸시·배포는 사용자 담당이다.

## 구현 범위

- 기존 Swift 복원 엔진을 읽기 전용 소스로 컴파일해 Unity의 로컬 자식 프로세스로 연결한다. 이동·공격·적/동맹 AI·턴 이벤트·피해·퇴장·승패·보상을 이 엔진이 판정한다. UI에서 별도 수식을 만들지 않는다.
- `AppBootstrap`에서 `IBattleSession` 구현을 주입한다. Core의 계약, Infrastructure의 프로세스/PCM 해석, Presentation의 보드/유닛/효과 재생을 분리한다. 셸이나 네트워크 서버는 사용하지 않는다.
- 아군 선택 → 이동 범위 → 칸별 실제 이동 → 취소/대기/공격. 이동은 대기/공격 전까지 취소 가능하다. 대기/공격 후 회색 진영 표시로 행동 완료를 구분한다.
- 왕건(id0)은 2턴 아군 시작에 `(10,6)`, 동행 기병258/259는 `(9,7)`/`(10,7)`에 등장한다. 처음부터 숨김 부대를 점유시키지 않는다.
- 캐릭터 표시 크기는 이전의75%. 제작된4방향 대기/이동/공격/스킬을 공용 아틀라스로 읽는다. 전체64프레임의 합집합 경계와 고정 발 기준을 공유한다.
- 이동 구간, 공격 단계, 효과음, 특수 연출은 원본 엔진이 완료 토큰을 발행한다. Unity가 재생한 뒤 같은 토큰으로 응답해야 진행한다. 대기 필드를 선제적으로 지우지 않는다. 잘못된 토큰은 거절한다.
- 원본 MCALL105는 기존 복원 디코더/렌더러로30프레임을 추출하고 원본2틱(0.1초)/프레임과 효과음을 사용한다. B00 배경을 기준으로 차이 픽셀을 표시하므로 Unity 인물과의 색 혼합까지 원작과 동일하다는 뜻은 아니다.
- 첫 전투 병과·레벨에서 사용 가능한 책략8종의 보유 원본 효과를 연결했다. 공유 아틀라스53,869바이트. 적의 혼란 등도 실제 효과 재생 후 판정 단계를 진행한다.
- 원본PCM WAV를 AudioClip으로 해석한다. CD 배경음악은 자료가 없어 사용하지 않는다. 2026-10-30 사용자 승인에 따라 미보유 파일/제작 포즈는 미적용으로 표시하고 진행하며 다른 곡으로 대체하지 않는다. 보유 파일의 디코딩 실패는 오류로 표시하고 완료 응답을 보내지 않는다.
- 전투 기록/미적용 자료, 승리/패배, 보유 금과 아이템 수, 다시 시작을 표시한다.

## 실행 준비

저장소 루트에서 다음 순서로 생성한다. 원본 자료 경로는 기존 `SANHA_ORIGINAL_ASSETS` 도구 설정을 따른다.

```sh
node scripts/game/export-unity.mjs
node scripts/game/export-unity-board.mjs
node scripts/game/export-unity-units.mjs
node scripts/game/export-unity-motion.mjs
node scripts/game/export-unity-effects.mjs
node scripts/game/export-unity-actions.mjs
node scripts/game/build-unity-native.mjs
node scripts/game/unity/check.mjs --compile-unity
```

그다음 Game.unity에서 Play → 새 게임 → 도입 → 출진 준비 → 전장 진입. 전투교본 질문에서 아니오를 선택하면 일반 전투로 진행한다. 전장은 전체 화면이다. 부대를 선택하고 지도 위 공격/스킬/도구/대기 버튼을 사용한다. 스킬/도구는 목록 선택 → 지도 대상 선택 → 사용 확정으로 진행한다.

네이티브 실행파일과 복사한 원본 데이터/음원은 StreamingAssets/SanhaNative에 생성하며 Git에서 제외한다. Library/Temp도 커밋하지 않는다. 새 환경은 위 생성 명령이 필요하다. 기존 원본 Swift 앱·안정본·사용자 저장은 수정하지 않는다.

## 검증

- Node5개 검사, 순수 C# 이동(지형 비용·적 인접 제한·아군 통과)/이동 취소/대기 및 기존 화면 흐름 검사, Runtime/Editor 컴파일 통과.
- `scripts/game/unity/tests/native-battle.py <native폴더> <결과json>`: 잘못된 완료 토큰 거부, 2턴 등장 좌표, 이동·취소 복원·대기, 정상 명령에 의한7턴 승리. 금1,000, 아이템ID87·87·76. 이 검사는 음향/화면을 재생했다는 증거가 아니다.
- `Sanha.Editor.BattleRuntimeCheck.Begin`: 격리된 임시 Unity 프로젝트의 실제 batch Play에서 코루틴 완료 응답, 선택/이동/취소/대기, 공격/AI, 책략 재생, 승리 보상을 검사한다. PCM22050Hz 해석도 검사한다. 이 검사는 실제 화면 수동 검수나 스피커 청취를 대체하지 않는다.
- 첫 Unity 화면 실행에서 누락된 JSON 연출 필드가 빈 객체로 읽혀 잘못된 완료 요청이 발생했다. 명시적hasPending 계약으로 수정하고, 실제 Unity batch Play에서7턴 승리까지 통과했다.

## 완료로 표시하지 않는 범위

- 기존 엔진의 원본 명령90·92는 승리 뒤 미복원 명령으로 남는다. 결과 화면과 기록에 그대로 노출한다. 전체 원본 복원이 완료됐다고 표시하지 않는다.
- 전투교본의 일부 상세 창은 안내 텍스트로 연결했다. 원본 Windows 메뉴/UI를 그대로 재현한 상태가 아니다. 새 프로필의 보상 없는 교본 흐름만 현재 어댑터 범위다.
- 상세 상태 아이콘·쇠약 포즈, 편성/장비, 세이브, 후일담/다음 스테이지 전이는 후속이다. 캐릭터의 장비/병과 수치 판정은 기존 엔진을 사용한다.
- 현재 실행 백엔드는 macOS 전용이다. 모바일/Windows 배포에는 C# 이식 또는 해당 플랫폼용 백엔드가 필요하다. 기존 MovementRange/ManualMoveState는 C# 이동 규칙의 기반이며 현재 실전 판정은 네이티브 엔진이다. 독립 앱 빌드는 아직 검증하지 않았다.

## 2026-10-31 화면 변경

전체 화면 전장·반응형 HUD·터치 입력·포함 한글 폰트·UTF-8 통신으로 변경했다. 기존 메뉴/마우스 안내와 아래 과거 실행 기록은 당시 상태이며, 현재 검사 범위는 [mobile-battle-hud.md](mobile-battle-hud.md) 참조. 이번 변경에서 Unity 실행은 사용자에게 맡기고 코드 검사/컴파일만 진행했다.

## 스킬·도구 선택 연결

지도 위 스킬/도구 버튼·현재 이름/설명·MP/수량·대상 및 범위 미리보기·사용 확정이 연결됐다. [조작과 검사 범위](battle-actions.md) 참조. 이 변경은 Unity 실행 검증과 구분하며, 위 과거 batch Play 기록을 현재 UI의 실행 증거로 사용하지 않는다.
