# 전체 화면 전장과 한글 표시

2026-10-31 사용자 요청. Unity 실행과 실제 화면 확인은 사용자가 진행한다. 이 작업에서는 코드 수정, 순수 C#/프로세스 검사와 설치된 Unity DLL 대상 컴파일만 수행했다. Unity 에디터를 실행하거나 마우스로 조작하지 않았다.

## 한글

- OS 폰트 탐색을 제거하고 Resources/Fonts/NanumGothic-Regular.ttf를 공용으로 사용한다. Game/ScenarioPreview 모두 같은 폰트를 사용하며 화면 전환 때 Resources 소유 폰트를 Destroy하지 않는다.
- TrueTypeFontImporter는 Dynamic/includeFontData=true로 설정한다. 폰트가 설치되지 않은 기기에서도 포함한 파일을 사용한다.
- 네이티브 엔진과의 표준 입출력·오류 스트림 인코딩은 BOM 없는 UTF-8로 명시한다. 잘못된 바이트를 물음표로 조용히 대체하는 대신 오류를 알린다. 기존 게임 데이터와 원본 Swift 소스는 수정하지 않았다.
- `wire-encoding.cs`가 실제 자식 프로세스로 한글을 왕복한다. 부모/자식 모두 LANG=C, LC_ALL=C. 부모의 기본 코드페이지20127(ASCII)에서도 원문이 보존됐다.
- CoreText의 글리프 검사에서 한글11,172자 전부 지원 확인. 폰트2,054,744바이트. 이는 Unity의 실제 글꼴 렌더링을 확인한 검사는 아니다.
- 공식 출처: [Google Fonts 원본](https://github.com/google/fonts/tree/main/ofl/nanumgothic). 변형 없이 포함했으며 [OFL](https://github.com/google/fonts/blob/main/ofl/nanumgothic/OFL.txt)은 폰트 옆과 StreamingAssets/Licenses에 함께 둔다.

## 화면/카메라

- 전투 카메라 pixelRect는 전체 Screen 영역이다. 이전1280×800의 부분 전장·상단 제목·우측 패널·하단 개발 문구를 전투 화면에서 제거했다. 도입/출진 준비 화면은 기존 좌표계를 유지한다.
- 20×20 전장 데이터와 전투 판정은 그대로다. 바뀌는 것은 카메라가 보여주는 범위다. 한 칸은 정사각형을 유지한다.
- 기본 배율은 `짧은 변 픽셀 / UI배율 / battleTileUiSize`를 기준으로 설정하며 짧은 변8~14칸 범위를 사용한다. 가로가 길면 열이 더 보이고, 큰 화면은 행·열이 더 보인다. 극단적으로 넓은 창에서는 기본 배율이 빈 지도 바깥을 드러내지 않도록 제한한다.
- UI배율은 모바일에서 보고되는 DPI, 없을 때는 화면 크기를 기준으로 계산한다. 화면 회전/크기 변경 시 배율을 다시 계산하며 사용자 줌 비율을 이어간다. DPI가 부정확한 기기의 체감 배율은 실기기 확인이 필요하다.
- 첫 화면은 도입 직후 동맹 부대 위치를 중심으로 보여준다. 기본 배율 복귀는 선택 칸을 우선한다. 전체 지도는 별도 버튼으로 가능하다.
- 공격자/대상, 이동 구간, 증원 위치가 화면 밖이면 카메라가 부드럽게 따라간다. 사용자가 지도를 움직인 직후에는2초 동안 자동 이동을 억제한다.

## 입력과 HUD

- 한 손가락 드래그: 지도 이동. 두 손가락: 중심점을 유지하며 확대/축소·이동. 짧은 탭: 칸/부대 선택.
- 드래그 임계값은 UI배율 기준8. 멀리 드래그했다가 시작점으로 돌아와도 탭으로 취급하지 않는다. 핀치 후 한 손가락만 남아도 선택 명령이 실행되지 않는다. 취소된 터치도 명령을 보내지 않는다.
- 마우스 드래그/휠을 유지하며 +/− 버튼도 제공한다. 터치가 만든 가상 마우스 이벤트는 지도에서 중복 처리하지 않는다.
- 좌상단: 선택 부대 이름/병과/HP/MP. 우상단: 턴/메뉴/확대축소. 좌하단: 전체 지도/턴 종료. 우하단: 선택 부대의 공격/대기/이동 취소.
- 버튼은 Safe Area 안에 둔다. 지도는 Safe Area 밖까지 그리므로 노치 주변이 빈 여백이 되지 않는다. 대사·메뉴·확인 창은 지도를 덮는 형태다.
- 설정/시작 화면/전투 기록/미보유 자료는 메뉴 안으로 이동했다. 대사나 메뉴 아래의 전투 버튼과 맵 선택이 함께 눌리지 않도록 차단한다. 전투 연출 중에는 맵 탐색은 가능하되 선택 명령은 차단한다.
- 후속 작업으로 지도 위 스킬/도구 목록·대상 선택·범위 표시·사용 확정을 연결했다. 상세 계약과 검사 범위는 [스킬·도구 조작](battle-actions.md)을 따른다.

## 공통 구조와 설정

- BoardCameraState/MapGesture: 순수 C# 투영·경계·줌·탭/드래그 상태. Unity 입력이나 전투 수식에 의존하지 않는다.
- BattleBoardView: 입력/카메라/보드 표시. BattleHud: 안전 영역 레이아웃/버튼/입력 차단. BattleController: 기존 전투 명령/완료 응답. App의 백엔드 주입 구조는 유지한다.
- MobileScreen/GameFont: 화면 배율과 폰트 공용화. HUD 스타일은 배율/폰트가 달라질 때만 만든다.
- Resources/Settings/runtime.json: fontResource, battleTileUiSize=64, battleMinShortCells=8, battleMaxShortCells=14. 숫자64를 낮추면 기본 화면에서 더 많은 칸이 보인다.
- legacy Input 모듈을 명시했다. 현재 네이티브 전투 백엔드는 여전히 macOS용이다. 모바일 입력 코드를 추가한 것을 모바일 앱 배포 완료로 취급하지 않는다.

## 검사

`node scripts/game/unity/check.mjs --compile-unity`

- 기존 Node5개/좌표·이동·화면 전이 검사 통과.
- 가로 비율 변화, 큰 화면, 회전, 정사각 투영, 움직이는 핀치 기준점, 지도 경계, 전체 지도/기본 배율, 드래그·핀치 취소 검사 통과.
- ASCII 기본 로케일의 실제 프로세스 한글 왕복 검사 통과.
- Runtime/Editor의 설치된 Unity DLL 대상 컴파일 통과. Unity 실행/실기기 터치/노치/HUD 외형은 사용자 확인 범위다.
- 커밋·푸시·배포 없음.
