# 스테이지 턴제 RPG 제작 순서

2026-10-30 사용자 요청. 웹은 기획·에셋 검토, Unity는 실제 게임 구현이다. 에디터 Play 버튼 실행과 게임 기능 완성을 구분한다.

## 화면 구조

시작 → 시나리오 → 출진 준비 → 전투 → 실제 판정에 따른 결과 → 후일담/다음 노드. Unity 씬 하나가 전투 한 개를 뜻하지 않는다. 공통 Game 씬이 스테이지 데이터를 공급받는다. 대화는 시나리오·전투 이벤트에서 재사용한다.

|---|---|---|---|
|1|화면 흐름|새 게임에서 이야기·준비·전장까지 진입/복귀|B00 연결. 실제 판정에 따른 결과/보상 표시|

단계별로 기존 Swift 구현·추출 데이터와 연결 위치를 대응시킨다. 첫 전투의 공통 구조를 만든 후 다른 전투는 데이터·이벤트 차이로 확장한다. 모든 전투를 별도 씬/스크립트로 복사하지 않는다. 원본 기존 관측은 재사용하고 현재는 구현·연결과 진행 장애 해결을 우선한다.

## 초기 보드 구현 계약 (아래는 당시 기록)

- Game.unity → AppBootstrap → GameFlowScreen. GameFlow(Core)가 시작/이야기/준비/전장 전이를 제어한다. 기존 ScenarioPreview는 참고 개발 뷰로 보존하되 시작 시 자동 표시하지 않는다.
- 첫 대화는 config/unity/first-stage.json의 introSceneIds만 재생한다. 마지막 대사를 확인한 뒤 출진 준비로 넘어간다. 후일담이나 임무 결과를 버튼으로 미리 성공 처리하지 않는다.
- 출진 준비는 현재 임무 설명과 전장 진입만 구현했다. 편성·장비·출전 판정은 다음 단계다.
- 전장은 SpriteRenderer의 월드 공간 지도, 실제20×20 좌표, LineRenderer 격자/선택 표시를 사용한다. 카메라와 같은 좌표변환으로 클릭을 해석한다.
- 좌상단(0,0), x는 오른쪽/y는 아래. 원본 terrain[y*width+x]를 그대로 사용. 월드 위치는(x,-y). 오른쪽/아래 경계 밖은 선택하지 않는다.
- 울타리·가옥·요새·병영 등의 모습은 기존 맵에 포함되어 있고 지형 종류도 원본400칸으로 읽는다. 별도 장애물 오브젝트/파괴·점유·보너스는 아직 연결 전이다. 지형 ID만으로 통행 가능을 임의 단정하지 않는다.
- 화면 왼쪽 전장에서 클릭 선택, 드래그 이동, 휠 확대/축소. 카메라 전체 보기와 격자 켜기/끄기. UI 버튼 클릭은 전장 선택과 분리한다.
- 병력 배치는 다음 단계다. 원본 deploymentCommands에는 숨김·등장 조건이 섞여 있으므로 모든 행을 초기 병력으로 펼치지 않는다. 실제 초기 이벤트 상태부터 연결한다. 시작 위치 변경도 별도 데이터로 검토하고 원본 기준 데이터는 유지한다.
- 병과 통행·이동/공격 범위·스킬·턴·AI·승패·보상은 완료로 표시하지 않는다. 결과 화면은 실제 outcome이 생긴 뒤 연결한다.

## 데이터와 재생성

기존 원본 assets/campaign/map-00.json과 assets/manifest.json(terrainNames)을 읽기 전용으로 재사용한다. 원본 파일 SHA256은 unity/board-export-manifest.json에 남긴다. 이는 기존 추출 자료의 재사용이며 새 REA 분석 결과가 아니다. 배경은 기존 exporter가 만든 Campaign/battlefield PNG를 그대로 공유한다. 추가 이미지 복사 없음.

```sh
node scripts/game/export-unity.mjs
node scripts/game/export-unity-board.mjs
node scripts/game/unity/check.mjs --compile-unity
```

원본 자료 위치 변경은 SANHA_ORIGINAL_ASSETS로 지정한다. 기본은 ~/Documents/ChatGPT/조조전/outputs/jojo-mac-preview/assets. 경로는 도구에서만 읽고 게임에 넣지 않는다. Unity 생성 데이터는 Resources/Battle/first-stage.json. 구조는 architecture.md 참고.

## 다음 작업의 승인/확인 단위

1. 전장 전체와 좌표·지형·카메라를 확인한다.
2. 실제 초기 아군·동맹·적군 배치와 제작 에셋을 연결해 확인한다.
3. 이동 범위와 이동/취소/대기, 이후 공격·책략을 순서대로 확인한다.
4. 적 턴과 승패 이벤트를 연결하여 첫 전투를 끝낸다.

커밋·푸시는 사용자 담당.

## 검증 기록

- Node3개 검사, C# 좌표 경계·선택·화면 전이 검사 및 Unity 참조 컴파일 통과.
- 실제 Unity import 및 Validate Campaign 성공. Game 씬 생성.
- Play에서 새 게임 → 도입4장면10대사 → 출진 준비 → 전장 → 준비 복귀 확인.
- 요새(9,11), 확대·드래그 후 병영(10,11) 선택 확인. 그림과 지형 좌표가 일치.
- 런타임 Exception/컴파일 오류 없음. 에디터 스크립트 reload 시 이전 폰트 참조 경고는 있었으며 새 Play의 한글 표시는 정상.
- 병력·전투·독립 앱 빌드는 후속 범위.

초기 병력 배치 적용 상세: first-stage-deployment.md. 기존 다음 작업1~2의 전장·정지 병력 표시를 완료했으며, 이동/전투와 턴 이벤트는 후속이다.
